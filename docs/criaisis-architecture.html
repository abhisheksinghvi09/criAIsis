Architecture walkthrough

Four specialists argue. One commander decides.

criAIsis spins up a simulated team of domain specialists — network, database, application, security — to debate a live incident inside the Slack thread where the firefighting already is. Each one is grounded only in its own runbooks. An Incident Commander agent then cross-examines them and names a root cause.

Mandate

The agent's role is deep read-only diagnostic investigation, never blind autonomous production remediation.

Go 1.27 · single binary PostgreSQL 16 + pgvector Claude Opus 5 · Messages API structured outputs HNSW + GIN · RRF hybrid search in-process job queue MCP read-only adapters Slack Block Kit

Six views for engineers: what deploys and what it talks to, the lifecycle of one investigation, the latency budget that drives every structural decision, the multi-tenant data and retrieval model, the safety boundary, and the simulation framework that lets all of it be tested without an outage.

Container map

One binary, one database, two model providers

Everything inside the dashed boundary compiles to a single statically linked Go binary. There is no message broker, no vector database, no Python sidecar, and no agent daemon. Three ingress paths converge on the same clash engine, and the only stateful dependency is one PostgreSQL instance.

Talking points

The layer order is enforced, not suggested

Router → Handler → Service → Repository. Handlers never touch SQL; repositories never hold business rules. cmd/criaisis/main.go is a composition root — it wires and handles lifecycle, and contains zero logic.

Two providers, because one cannot do both

Anthropic exposes no embeddings endpoint, so the chat and embedding contracts are separate interfaces with separate credentials. The pgvector column is fixed at 1536 dimensions, which pins the embedding model choice.

No Redis, deliberately

A buffered Go channel behind a JobQueue interface satisfies MVP volume with zero operational surface. The interface is the seam: swapping in Redis later touches one constructor in the composition root.

External tools are hands, not brains

Prometheus and CloudWatch are reached through read-only adapters the orchestrator calls. The orchestration itself stays native Go — an autonomous agent loop wandering a cluster cannot meet a 25-second incident SLA.

Request lifecycle

The 2-stage clash, and the persona boundary that holds it together

One incident, three stages. Stage 1 fans out to every enabled specialist concurrently; Stage 2 cross-examines their claims into a verdict; Stage 3 answers follow-ups in-thread. The persona boundary is the spine of the whole design — follow the dashed amber edges to see the four places it is enforced.

The boundary, enforced at four points

Who participates

Personas are loaded per workspace and filtered to those an operator left enabled. A workspace with no enabled personas fails fast rather than running a silent, empty debate.

What each specialist can see

SearchHybrid is scoped to (workspace_id, persona_id) in the SQL WHERE clause. The database specialist cannot retrieve a network runbook — not by prompt instruction, but because the rows are unreachable. This is the zero-cross-persona-leakage requirement, and an integration test asserts it directly.

How the prompt is composed

The read-only mandate is prepended by the engine to every persona's system prompt. Operators may edit their persona's prompt freely; they cannot edit away the boundary, because it is not stored in the editable field.

What may be cited

Models are asked to return the chunk IDs they relied on. Every returned ID is checked against the set actually placed in that prompt, and anything else is discarded before the turn is written. A hallucinated citation never reaches the post-mortem record.

Talking points

Structured output, not prose parsing

Both stages pin the response to a JSON schema via output_config.format. Classification, ownership, confidence and citations arrive as typed fields, so the transcript never depends on a regex over model prose. An unparseable classification fails the synthesis rather than being silently coerced.

Graceful degradation is structural

A specialist goroutine never propagates its error — a failure is recorded against that persona and the siblings continue. Three surviving specialists still produce a consensus. Only a total washout aborts the clash.

Effort is tiered by stage

Stage 1 runs four-wide against a 10-second budget, so it requests low reasoning effort. Stage 2 is a single call where depth is the whole point, so it requests high. Same model, different spend, driven by the latency budget.

Stage 2 cites Stage 1's evidence

Retrieval happened per persona, so the commander runs no fifth search. Instead the Stage 1 citation snapshots are pooled, and the verdict may cite only from that pool — the consensus can never rest on evidence no specialist ever saw.

Ingress & timing

The latency budget is the architecture

Slack gives a slash command 3 seconds to acknowledge; an incident commander gives an answer about 25. Nearly every structural decision — the in-process queue, the parallel fan-out, one shared embedding call, tiered reasoning effort, the 5-second probe cap — falls out of that budget.

Talking points

Acknowledge first, work later

Both ingress paths persist the incident and return immediately. The clash runs on a worker, not in the request. A webhook burst therefore cannot time out Slack or Grafana — it fills a bounded queue and is rejected with backpressure at the edge.

Fan-out is what buys Stage 1

Four sequential specialist calls would spend the entire budget before the commander started. Running them concurrently makes Stage 1 cost one call's latency, not four.

Webhooks get a wider window

A webhook-triggered incident targets under 30 seconds rather than 25, because parsing the provider payload into an IncidentContext happens before the clock that matters to a human starts.

Telemetry probes are capped, not trusted

A diagnostic probe gets 5 seconds. Past that it is cancelled and the specialist is handed an explicit "unavailable" note instead of a result — a slow Prometheus degrades the evidence, never the deadline.

Tenancy & retrieval

One store, one invariant, two ranking signals

Relational records and 1536-dimension vectors live in the same PostgreSQL instance, which removes an entire class of dual-write drift. Every table downstream of workspaces carries workspace_id with a cascading foreign key, and every repository method takes a typed WorkspaceID it must put in the WHERE clause.

Talking points

Why both ranking arms are needed

Incidents are full of strings that must match exactly — exit code 137, FATAL: remaining connection slots, a stack frame path. Dense search blurs those; keyword search nails them and misses paraphrase. Fusing the two ranks costs one SQL statement and needs no tuned weight.

Citations are stored twice, on purpose

A turn keeps referenced_chunk_ids UUID[] for joins, and an immutable snapshot of the excerpt text in metadata JSONB. Six months later the runbook may be rewritten or deleted; the post-mortem still shows what the agent actually read.

The transcript cannot be rewritten

DebateTurnRepository exposes Create, GetByID and ListByIncident — and deliberately no update or delete. Audit durability is a property of the interface, not of reviewer discipline.

Isolation is tested adversarially

An integration suite stands up two workspaces, ingests into both, and asserts that vector search, document lookup and incident listing never cross. A second case asserts the same across personas inside one workspace.

Safety boundary

Zero blast radius, by construction rather than by policy

The product's central promise is that the agents cannot break production. That promise is worth only as much as its weakest enforcement, so it is held in three different places: the tool contract has no mutating method to call, the registry caps every probe, and remediation is emitted as text for a human to run.

Talking points

The contract has no write verb

DiagnosticTool is three methods: a name, a description for the model, and Execute returning a result. There is no Apply, no Mutate. An adapter author cannot add one without changing an interface that the whole engine compiles against.

The timeout lives above the adapters

The registry wraps every call in a 5-second context before dispatch. A careless adapter that ignores deadlines still gets cancelled, because the ceiling is not the adapter's to honour.

Remediation is advice, not action

Runbooks legitimately contain destructive commands — terminating hung backends, for instance. The agent may quote one. It has no channel to execute one. The gap between quoting and running is the entire security model, and it is a gap in capability rather than in instruction.

Enterprise review is the real constraint

A tool that needs cluster-admin credentials faces a six-to-twelve month security review. A tool that needs a Slack app and read-only metrics access does not. The posture is a go-to-market decision as much as a safety one.

Verification

Reproducing an outage without having one

A multi-agent debate is hard to test: the output is prose, the input is a production disaster, and the model is non-deterministic. The simulation framework splits the problem — deterministic fixtures with known ground truth, and two run modes that prove different things.

Talking points

Offline mode proves plumbing, never judgement

The stub returns schema-valid JSON with a constant classification. That is enough to exercise retrieval scoping, citation filtering and persistence on every commit — and it is deliberately incapable of validating diagnosis, so no one is tempted to read a green CI run as evidence the agents are correct.

The fake embedder still ranks

It hashes tokens into buckets and normalises, so cosine similarity tracks lexical overlap. Retrieval returns plausibly-ordered neighbours offline, which is what makes the wiring assertions meaningful rather than trivially true.

Fixtures carry ground truth

Each scenario states its true classification and owning domain. The set spans all three failure modes on purpose: a pure-infra packet-loss event, a code-level transaction leak, and a hybrid OOM crashloop where a code defect exhausted an infrastructure limit.

Hybrid is the hard case

Pure infra and pure code are relatively easy to separate. The failure mode worth benchmarking is the one where a release caused the capacity problem — which is precisely where a single flattened summary tends to blame the symptom.

Outcomes

What it delivers, and to whom

Incident Commander

A cross-domain hypothesis before the specialists wake up

Four grounded opinions and a reasoned verdict inside the thread, in about the time it takes to open a dashboard — with the contradictions named rather than averaged away, and a root cause labelled code, infra, or hybrid so the page goes to the right team first.

Platform / SRE admin

Runbooks that earn their keep

Documentation stops being a wiki nobody opens at 3am and becomes the retrieval corpus behind every hypothesis. Gaps announce themselves: a persona with no relevant runbook says so and reports no confidence, rather than improvising.

Paged specialist

Catch-up without re-litigating

Joining mid-incident means reading a transcript that shows what was ruled in, what was ruled out, and the exact runbook excerpt behind each call — then asking one persona directly with an @mention.

The organisation

Post-mortems that survive the runbook

Every debate is an append-only record with immutable citation snapshots. Months later, when the documentation has moved on, the transcript still shows exactly what the agents read and concluded.
